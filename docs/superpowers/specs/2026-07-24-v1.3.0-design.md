# Tayyibat v1.3.0 — design spec

**Date:** 2026-07-24 · **Version:** 1.3.0+10 · **Schema:** v5
**Status:** approved (decisions locked with the user)

Five independent features on branch `claude/tayyibat-ios-app-ftYsJ`. Each is
built test-first with its own commit; analyzer and tests stay green throughout.

## Locked decisions
- Ship all five together as **v1.3.0** (separate from the submitting 1.2.1).
- **Apple Health:** read steps + active energy and **offset the calorie budget**.
- **Food bank:** ~**150** hand-authored Egyptian/Arabic dishes.
- **Plan scoring:** **combine** manual check-off with an auto-compare of logged meals.

## Schema v5 (additive)
- `meals.source TEXT` — provenance: `ai` (default/legacy), `food_bank`, `manual`.
- `meal_plans.started_at INTEGER` — anchors plan day 0 to a calendar date once
  the user commits to a plan (null until committed).
- Migration: fresh-create includes both; `_addV5Schema` ALTERs on v4→v5. Covered
  by fresh-create and upgrade tests via `sqflite_common_ffi`.

## 1. Food bank (log without a photo)
- **Data:** `lib/data/food_bank_data.dart` — ~150 `FoodBankItem`s. Fields:
  `nameAr`/`nameEn`, `category` (breakfast/lunch/dinner/street/drinks/sweets),
  `zone` (green/yellow/red per the Tayyibat RULES — honest: koshari/ful/dairy are
  red/yellow), `portionAr`/`portionEn`, `caloriesKcal`, `proteinG/carbsG/fatG`,
  optional bilingual note.
- **Model:** `FoodBankItem` with locale-aware getters.
- **UI:** `features/food_bank/food_bank_screen.dart` — search (matches ar+en),
  category chips, list with zone badges + kcal → detail sheet → "Log this meal".
- **Log:** `MealRepository.logFromFoodBank(item, {portions})` writes a `Meal` with
  one `FoodItem`, score via `recomputeScore`, nutrition scaled by portions,
  `source='food_bank'`, no photo. `notifyListeners`.
- **Entry points:** Today ("Log from food bank") and the capture screen.
- **Tests:** data integrity (all items valid zone/nutrition, ar+en non-empty),
  search filter, `logFromFoodBank` persistence + score + nutrition.

## 2. Name fields (first / last / nickname)
- **ProfileService:** add `firstName`, `lastName`, `nickname` (optional, on device).
  One-time migration: existing `displayName` → `firstName`. Greeting name =
  `nickname ?? firstName` (falls back to none). Keep `displayName` getter as
  `nickname ?? [first last].join()` for any other reader.
- **Onboarding:** the welcome "about you" step collects first + last + nickname.
- **Settings:** edit all three.
- **Tests:** get/set/reset, greeting derivation, displayName→firstName migration.

## 3. Apple Health (HealthKit)
- **Dep:** `health` package. **Native (iOS):** HealthKit entitlement in
  `Runner.entitlements`; `NSHealthShareUsageDescription` in Info.plist.
- **Service:** `HealthService` — request read access to `STEPS` and
  `ACTIVE_ENERGY_BURNED`; fetch today's totals; expose `steps`, `activeEnergyKcal`,
  `authorized`, `available`. Degrades gracefully (denied/unsupported → nulls, no
  crash).
- **Budget offset (pure fn, tested):** `calorieRemaining(goal, consumed, burned)`
  `= goal + burned - consumed`. Today's calorie card shows "goal + burned" and the
  adjusted remaining; a health card shows steps + burned.
- **Settings:** connect/disconnect (re-request permission) toggle.
- **App Store:** new capability + a Health privacy-label entry to add at submission.
- **Tests:** `calorieRemaining` and the card's displayed breakdown (pure logic);
  native fetch is integration-only.

## 4. More suggestion variety
- **Server (`analyze/index.ts`):** `suggest` → **5** options; accept optional
  `meal_type` (any/breakfast/lunch/dinner) and a `variety` seed so "regenerate"
  differs. `plan` gets a stronger "make each week different" instruction.
- **Client:** `SuggestionsScreen` — meal-type filter chips, render 5 cards,
  regenerate stays locale-aware. `SuggestionService.suggestMeals({mealType})`.
- **Tests:** list parser already handles N; add meal_type/variety threading tests
  and a 5-item parse test.

## 5. Plan adherence (planned vs actual)
- **Anchor:** committing a plan sets `meal_plans.started_at` (day 0 = that date).
- **Scoring (pure fn, tested):** `planAdherence({days, doneFlags, loggedDates,
  startedAt, today})` → 0–100. A planned day is "met" if the user manually ticked
  its meals **or** logged ≥1 meal that calendar day; blend per-meal manual
  completion with per-day logged coverage. Only days up to `today` count.
- **UI:** plan tab gains a "commit plan" action and a planned-vs-actual card
  (score + per-day met/missed), reading logged-meal dates from `MealRepository`.
- **Tests:** `planAdherence` across done-flags × logged-date × date-window cases.

## Cross-cutting
- ~40 new bilingual strings (ar/en parity enforced by existing tests).
- `pubspec` → 1.3.0+10; CLAUDE.md roadmap + App Store/Play release notes.
- Verify (analyzer + full test suite), dispatch a code-review subagent, fix
  findings, push. Flag the HealthKit privacy-label update for submission.

## Out of scope
- Android Health Connect UI polish (the `health` package covers it, but iOS is
  the focus this round).
- Writing data back to HealthKit (read-only).
- External food APIs (the food bank is a curated local dataset).
